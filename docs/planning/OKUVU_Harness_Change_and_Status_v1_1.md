## Part 1 — What changed, in plain language

### 1.1 The big picture

Before this change, the harness could run **one session** with a persona and score it. The spec asked for a **multi-session simulated conversation runner**: one synthetic client persona "lives" across multiple sessions separated by realistic gaps (days), the client side is played by a **dedicated user-simulator agent**, the memory/continuity of the product is **asserted** (C1–C5), and everything is orchestrated through **resumable API endpoints** with cost rails and a bulk **.xlsx export** for the SME. All of that now exists.

### 1.2 Story-by-story (spec IDs preserved)

| Story | What was built | Where it lives now |
|---|---|---|
| **TH-S32** Persona bank | Personas are now first-class DB rows (`CorpusCase` type `persona`) with `turns` (seed dialogue) + `persona_meta` (language, risk profile, escalation tendency). Old `persona-scripts.ts` is demoted to seed data. Create/import/list via tRPC. Starter set of **6 personas seeded** (the 5 built-ins + spec §6.1 P01). | `schema.prisma`, `corpus.ts` router, `scripts/seed-persona-bank.mjs` |
| **TH-S33** User-simulator | A *separate LLM agent* that plays the client: reacts to A2's replies, temp 0 + deterministic seed per turn, **refuses to run on A2's own model** (no self-play). In sandbox it uses deterministic canned turns (no API cost). | `lib/user-simulator.ts` (new) |
| **TH-S34** Multi-session orchestrator | One synthetic thread, N sessions, `gap_before_ms` injected between sessions, per-turn telemetry. Split out of the old single-session `pipeline-runner`. Crash-safe: reconstructs exactly where the thread left off from durable state. | `lib/conversation-runner.ts` (new), `pipeline-runner.ts` (split) |
| **TH-S35** Run-batch API | `POST /api/run-batch` (idempotency key, **dry-run** mode with zero LLM calls), `GET /api/run-batch/{id}` (status/progress/cost), `POST /api/run-batch/{id}/advance` (processes next due step; resumable forever). | `app/api/run-batch/*` (3 new route files) |
| **TH-S36** Continuity asserts C1–C5 | The runner now *verifies* memory/continuity instead of assuming it: session summaries exist, cross-session recall, no re-onboarding, gap acknowledgment, suppression of machine signals. The 20-Sep "worker down but test passed" failure class is now a hard **C1 fail**, never a silent pass. | `lib/continuity-asserts.ts`, `lib/session-close-runner.ts` (new) |
| **TH-S37** Cost/safety rails | New `ConversationRun` model. Rails: **cost ceiling** per run (exceeding → status `incomplete`, not error), **staging-only** enforcement, **canned-refusal** in staging (real-model mode can't silently run canned), model pinning. | schema.prisma, `conversation-runner.ts` |
| **TH-S38** Bulk export | One-click **.xlsx** with Summary / Turns / Sessions sheets, scoped to a run batch, bounded at 20k rows, fallback-count column per turn. Wired as tRPC procedures on the results surface. | `lib/workbook-export.ts`, `routers/results-export.ts` (new) |
| **§2** Nav prune | Dashboard nav reduced to the **5 MVP screens**. Deferred screens are *not deleted* — still reachable by URL, and `NEXT_PUBLIC_HARNESS_FULL_NAV=1` restores the full nav. | `ScreensNav.tsx` |

### 1.3 How functionality actually changes (user-visible behavior)

| Before | After |
|---|---|
| Persona = hardcoded script in code | Persona = DB row; add/import without a deploy (via `corpus.createPersona` / `bulkImportPersonas`) |
| One session per run, single-shot | N sessions per run across one thread, with configurable gaps |
| Client replies were scripted | Client replies generated by a dedicated simulator agent (real model in staging, deterministic in sandbox) |
| "Pass" could hide a dead worker | Worker-down / stage-failure ⇒ run is `incomplete`/C1-fail, never clean |
| No cost awareness | Every run tracks cost; ceiling breach halts the run as `incomplete` |
| Results only viewable in-app | Export the whole batch to .xlsx (Summary/Turns/Sessions) for the SME |
| 14-item nav | 5-screen MVP nav (full nav behind a flag) |

### 1.4 Database changes — **additive only**

Migration `20260922080000_add_conversation_runner`:
- `CorpusCase` + `turns` (Json), + `persona_meta` (Json, nullable)
- New table `ConversationRun` (batch orchestration state: progress, cost, gap mode, results ref, idempotency key)
- No column dropped/renamed; nothing existing becomes wrong. Safe on any environment.

**Applied already:** `test_harness` Neon branch ✅ (migrated + 6 personas seeded). **Not yet applied:** Neon `main` — one command, see Part 3.

### 1.5 Dev-only auth bypass (from the previous session, still in this diff)

`apps/test-harness/src/lib/auth.ts` + `.env.example`: `HARD_HARNESS_LOCAL_DEV_BYPASS_AUTH=true` gives a synthetic sandbox-only session locally — no Google login. It **refuses to boot in production** and never applies to staging/beta. Remove the flag from your local `.env.local` when done testing; it is not committed anywhere.

## Part 4 — Try it yourself (5 minutes)

```bash
# T1
cd apps/worker && pnpm dev
# T2
cd apps/api && pnpm dev
# T3
cd apps/test-harness && pnpm dev
```

1. `http://localhost:3002` → sign-in bypassed locally (or Google) → Dashboard shows 5-screen nav.
2. `/conversations` → persona picker shows the 6 seeded personas (incl. **P01 — Continuity probe** from the spec).
3. **Dry-run, zero cost:** `POST /api/run-batch` with `{ "personaId": "<id>", "sessions": 2, "gapMode": "story-time", "environment": "sandbox", "dryRun": true, "idempotencyKey": "try-1" }` → then tick `GET /api/run-batch/{id}` — you get the full plan (sessions, gaps, asserts) without a single LLM call.
4. Remove `"dryRun"` (sandbox still canned, still free) → `advance` until complete → check C1–C5 assert results on the run.
5. `/results` → export the batch to **.xlsx** → open: Summary/Turns/Sessions sheets, fallback counts per turn.
