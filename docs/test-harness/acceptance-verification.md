## Known gaps re-confirmed for this story

A first live test connected as `neondb_owner` (the only role available at the time) and found every query returned rows from every environment — that role has `rolbypassrls=true`, which makes Postgres skip RLS unconditionally, overriding `FORCE ROW LEVEL SECURITY` (which only binds the table *owner*, not a `BYPASSRLS` role). A dedicated role, `test_harness_app` (`NOSUPERUSER NOCREATEDB NOCREATEROLE NOBYPASSRLS`, granted `SELECT/INSERT/UPDATE/DELETE` on all public-schema tables plus default privileges for future ones), was then created. ## UPDATE 2026-08-20 — the app was completely unrunnable until today

Everything above this line was verified via `tsc`/`vitest`/direct router calls — none of it ran the app itself with `pnpm dev`. When that was finally done, **every single page 500'd**, including ones with no data dependency at all (`/auth`). Root cause: Turbopack (Next 16's default bundler) cannot resolve the `.js`-suffixed ESM imports `apps/api`'s entire codebase uses (a confirmed, currently-open upstream Turbopack limitation — [vercel/next.js#82945](https://github.com/vercel/next.js/issues/82945)), which `apps/test-harness`'s direct-import architecture (TH-S09/S10/S18/S21/S22/S27) depends on. `tsc --noEmit` and `vitest` never caught this because they use different module resolution than Next's dev/build bundler — this is exactly the kind of gap unit tests structurally cannot catch, and it existed silently through the entire sprint.

Fixed (see `docs/test-harness/running-locally.md` for the full explanation and `git log` for the exact commit): switched `apps/test-harness` to build with classic webpack instead of Turbopack (`--webpack` flag + a `resolve.extensionAlias` config, the standard fix for this exact scenario), plus two follow-on GCP-client-library-vs-bundler issues surfaced once the first fix worked (a phantom `protobufjs` dependency in `@google-cloud/aiplatform`, fixed via pnpm `packageExtensions`; and `@google-cloud/tasks`/`aiplatform`'s dynamic JSON config loading, fixed via webpack `externals`). **Re-verified after all three fixes: all 15 routes compile and serve without error**, `tsc`/`vitest` (127/127) still pass, `apps/api` unaffected. This is now genuinely runnable, not just genuinely tested.

This is added here rather than silently fixed and forgotten because it's a significant, previously-invisible finding: **running the actual app was necessary and this sprint had never done it before this point.**

8. **Beta S3/S4 "100% capture" is an operational claim about production traffic**, not something a unit-test suite can establish. The capture mechanism (session-close → A13/A15 worker trigger → `SessionSummary`) is implemented and tested at the mock level; actual capture-rate needs to be measured against real beta sessions after deployment, per the "S3/S4 capture-rate proxy" metric already named in `docs/test-harness/ethics-review-prep.md`.
