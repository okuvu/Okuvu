## Overview

After A10A generates each session summary, run a lightweight Flash-Lite extraction job that reads the new summary alongside the existing `UserMemory` object and produces an updated memory object. Runs fully offline — zero session latency impact. Uses the same Cloud Tasks pipeline already built for A10A.

---

## Architecture

### Integration point

Memory extraction hooks into `apps/worker/src/lib/summary.ts` at line ~188, immediately after the `SessionSummary` upsert with status `COMPLETED` succeeds. Extraction failure **must not** fail the A10A job.

### Data flow

```
Session close → Cloud Tasks → POST /tasks/summary → generateSessionSummary()
  → Flash-Lite generates summary
  → Write SessionSummary COMPLETED
  → updateUserMemory(userId, summary, sessionNumber)    ← NEW
     → Read existing UserMemory (null on first)
     → buildMemoryExtractionPrompt(existing, summary, sessionNumber)
     → Flash-Lite at temperature=0.0, maxOutputTokens=800
     → Parse JSON → UserMemory.upsert()
     → On any error: log and return (don't throw)
  → Return { status: 'completed' }
```

## Files

### New: `apps/worker/src/lib/memory-extraction.ts`

Exports `updateUserMemory(userId, newSessionSummary, sessionNumber)`.

- Reads existing `UserMemory` via Prisma (`findUnique`)
- Builds prompt using `buildMemoryExtractionPrompt()`
- Calls `generateContent()` from `./vertex-ai.js` with `temperature: 0.0`, `maxOutputTokens: 800`
- Parses JSON result into a `UserMemoryUpdate` interface
- Upserts `UserMemory` record (create on first session, update on subsequent)
- On any error (Flash-Lite failure, JSON parse failure, DB error): logs error and returns — does not throw

### New: `apps/worker/src/prompts/memory-extraction-v1.0.txt`

Prompt template used by `buildMemoryExtractionPrompt()`. Template variables:
- `${existing_memory}` — JSON string of current UserMemory, or `null`
- `${new_session_summary}` — the A10A-produced session summary text
- `${session_number}` — the current session number

Rules enforce: explicit-only facts, merge-not-overwrite (unless contradicted), max 15 words per item, session number bracketed in significant events, `emotional_baseline` null for < 3 sessions.

### Modified: `apps/worker/src/lib/summary.ts`

Add import of `updateUserMemory` and call it after the COMPLETED upsert succeeds (line ~188), wrapping in a try-catch to ensure extraction failure never propagates.

## Error Handling

| Failure | Behavior |
|---------|----------|
| Flash-Lite call fails | Log error, skip memory update, return normally |
| JSON parse fails | Log raw output, skip memory update, return normally |
| DB upsert fails | Log error, skip memory update, return normally |
| Empty arrays in output | Valid — do not treat as errors |
