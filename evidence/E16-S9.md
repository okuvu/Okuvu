## 8. Deliberate decisions / things NOT done

1. **The gate is `chat_access_requested_at`'s 30-day window, not `chat_access_granted`.** Verbatim from the story. Consequence worth stating: a pairing whose client granted access *without* the therapist ever having asked (possible today through the admin Add-Client flow) is refused by this view, because there is no request timestamp to open the window. Report Card / Session Prep keep their own `chat_access_granted` gate — untouched here. If the intent is "grant OR fresh request", that is a one-line change to `chatAccessWindow`, and it needs a product decision, not a guess.
2. **Both refusals throw `TRPCError('FORBIDDEN')`** rather than returning `{ granted: false, turns: [] }`. A discriminated union would put the transcript and the refusal in one response type, where a later refactor could leak content; a thrown error has no content field at all.
3. **The refusal branch reads `clients.detail`** to fill the consent chip. That is an existing clinical read and appends its own `VIEW_CLIENT_DETAIL` row, so a refused conversation view can leave two log rows. Chosen deliberately: it reuses the existing request-access UI instead of duplicating it, and it discloses nothing to a therapist who is not on the client's roster (that path throws too, and the page shows a generic notice).
4. **No conversation view in the mobile app, no writes, no message composer.** The story is a portal read; `Turn` writes stay in `apps/api`.
5. **`apps/therapist-portal/src/lib/auth.ts` was not touched** (another agent owns the PII-logging cleanup there). Note that today's `auth.ts` still logs sign-in email addresses at `[AUTH] Successful sign-in: …` and `[AUTH] Unauthorized sign-in attempt: …` — visible in the gate transcript above. That is pre-existing and out of my lane, but it means "no personal data in the portal's logs" is **not** true portal-wide until that agent's change lands; it *is* true for every code path this story added.
6. **`next dev` regenerated `apps/therapist-portal/AGENTS.md`** (Next 16's agent-rules block). Deleted rather than committed — it is a dev-server artifact, not part of this story.
