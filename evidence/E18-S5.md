## 3. The signing trap — and the key this build actually used

`apps/mobile/android/app/build.gradle` reads `rootProject.file('keystore.properties')`, which is
gitignored (`apps/mobile/.gitignore:48`), so a fresh worktree has **no signing config at all**.
Two distinct hazards were checked, and both are real:

### 3a. The file present in the main checkout is the PLACEHOLDER key — do not use it

```
$ keytool -list -v -keystore /opt/data/okuvu/ts/apps/mobile/android/upload-keystore.jks
Alias name: upload
Entry type: PrivateKeyEntry
Owner: CN=Okuvu LOCAL PLACEHOLDER Upload Key, OU=DO NOT SHIP, O=Okuvu, L=Local, ST=Local, C=IN
Valid from: Tue Oct 27 12:09:35 UTC 2026 until: Sat Mar 14 12:09:35 UTC 2054
	SHA256: 77:C1:EA:A9:80:AF:FC:75:03:F9:BB:85:4C:6A:FB:C6:96:EE:CF:31:CA:99:6C:D3:0D:7E:DE:DC:0E:FE:6A:19
Signature algorithm name: SHA384withRSA
Subject Public Key Algorithm: 4096-bit RSA key
```

`OU=DO NOT SHIP`, fingerprint `77:C1:EA:…`. That keystore and its `keystore.properties` were
**not** copied into the worktree.

### 3b. `assemble*Release` silently emits an UNSIGNED apk when the file is missing

The fail-fast guard in `build.gradle` matches only `/bundle.*Release/` — it does **not** cover
`assemble`. Proven by moving `keystore.properties` out and building:

```
$ mv apps/mobile/android/keystore.properties <scratch>/
$ (cd apps/mobile/android && ./gradlew :app:assembleProdRelease)     # exit 0, no error
$ find build/app/outputs -name "*.apk"
build/app/outputs/apk/prod/release/app-prod-release-unsigned.apk      # <-- "release" but unsigned

$ apksigner verify --print-certs app-prod-release-unsigned.apk
DOES NOT VERIFY
ERROR: Missing META-INF/MANIFEST.MF
(exit 1)

$ cat build/app/outputs/apk/prod/release/output-metadata.json
"variantName": "prodRelease",
"outputFile": "app-prod-release-unsigned.apk"
```

A green build therefore proves nothing about signing. That is why §6 reads the certificate back out
of the produced APK instead of trusting the build log.

## 8. Reproducibility

- **Deterministic given the same environment:** the final build and an immediately preceding build
  of the same command produced byte-identical output — same 59,110,168 bytes and the same
  `626d9989…e465c`. So the SHA-256 below can be re-derived, not just trusted.
- **NOT reproducible from a clean worktree.** `keystore.properties` is gitignored and absent from
  any clone, and without it `assembleProdRelease` exits 0 while emitting
  `app-prod-release-unsigned.apk` (§3b). Anyone re-running this must first place a
  `keystore.properties` pointing at the real key:
  `storeFile=/opt/data/okuvu/keys/okuvu-upload.p12`, `keyAlias=upload`, both passwords from
  Secrets Manager `evia-beta/android-upload-keystore`. Without that, any "release" APK produced is
  unsigned and uninstallable — the failure is silent in the build log.
- Also gitignored and required: `apps/mobile/android/local.properties` (`sdk.dir`,
  `flutter.sdk`), which `flutter build` rewrites itself.

## 9. Clause 3 — "installs and launches on the same device used for the smoke test": BLOCKED-ON-E18-S4

No emulator was created, booted, or counted as a pass. **The third clause is not met and is not

run on that same handset:

```bash
export PATH=$HOME/.local/android/platform-tools:$PATH
APK=/opt/data/okuvu/wt/E18-S5/apps/mobile/build/app/outputs/flutter-apk/app-prod-release.apk

adb devices -l                                   # expect the E18-S4 device, state "device"
sha256sum "$APK"                                 # must be 626d9989…e465c before installing
adb install -r -d "$APK"                         # expect "Success"  (59.1 MB, allow ~1 min)

# identity actually on the device matches the recorded artifact
adb shell dumpsys package ai.okuvu.app | grep -E "versionName|versionCode|targetSdk"
#   expect versionName=1.0.5  versionCode=6  targetSdk=36

# the installed signature is the upload key, not the placeholder
adb shell dumpsys package ai.okuvu.app | grep -A3 "signatures"    # compare with §6 digest

adb shell am start -n ai.okuvu.app/ai.okuvu.app.MainActivity
sleep 15
adb shell pidof ai.okuvu.app                     # non-empty => process alive (did not crash)
adb logcat -d -t 300 | grep -iE "AndroidRuntime|FATAL|FlutterError" | tail -30
                                                 # expect no FATAL EXCEPTION
```

Failure modes to expect, all diagnosable from the above:

- `INSTALL_FAILED_UPDATE_INCOMPATIBLE` — an `ai.okuvu.app` signed with a different key is already
  on the handset (e.g. an earlier placeholder-signed build from E18-S2). Fix:
  `adb uninstall ai.okuvu.app`, then install again. Same key as the AAB, so Play-installed users
  are unaffected.
- Immediate crash containing `FlavorNotSpecifiedException` — the APK was built without
  `--dart-define=FLAVOR=prod`; rebuild with the §4 command.
- `INSTALL_FAILED_OLDER_SDK` — device below API 24.
