## 1. What was actually broken

Two gaps, both already logged by earlier stories, plus a false premise in the story's setup.

**(a) A dead classifier silently meant "no crisis".** `apps/api/src/agents/a1/agent.ts`'s
`fallbackOutput()` returned `safetyState: 'S2', crisis_language_detected: false` for every technical
failure. S2 routes to A2, so a user typing *"I want to die"* while Bedrock was throttling got a
supportive chat reply. That is the fail-open hole E17-S1 §7 and E17-S2 §465 logged from opposite
ends.

**(b) Every technical failure looked the same to the user.** `bedrock.ts` returned
`SAFE_FALLBACK` — *"I'm here to support you. Could you tell me more about how you're feeling?"* — for
a throttle, a timeout and a missing model alike, and nothing on the wire distinguished it from a real
reply. E17-S2's finding was exactly this: throttling degraded to the generic supportive fallback
rather than a visible model-unreachable path.

**(c) The premise "the audit chain has a verify endpoint in the existing code" was false.**
`grep -rni "audit.chain\|prev_hash\|createHmac" apps packages` on the base commit returned nothing,
`packages/prisma/schema.prisma` has no audit table, and `docs/AGENT-CODE-STANDARD.md` §10 lists
*"1. Hash-chained audit log (tamper-evident turn history)"* as a **not-yet-ported** idea from
`reference/python-core/`. The only implementation in the project is
`reference/python-core/okuvu/audit.py` (not in this repo — it lives in the demoted `reference/`
tree outside `ts/`). So the chain *and* its verify endpoint were built here, as a faithful port (§4)
rather than as a new design.

## 2. The fix, per failure shape

| Where it fails | Before | After |
| --- | --- | --- |
| A1 unreachable, message is a disclosure | S2 → A2 chat | **S4 → crisis path** (`CRISIS_RESPONSE`, helplines, persisted, `crisis_flag_detected`, `safety.code: 'CRISIS_FLOOR'`) |
| A1 unreachable, no crisis language | S2 → A2 chat (an *ungated* model reply) | **`SAFETY_UNAVAILABLE_RESPONSE`**, A2 never called, `fallback_source: 'safety_unavailable'` |
| A2 unreachable after a real classification | `SAFE_FALLBACK` generic sentence | **`MODEL_UNAVAILABLE_RESPONSE`** (or the steadier `A9_POST_S2_FALLBACK` at S2), `fallback_source: 'model_unavailable' \| 'model_throttled'` |
| A1 throws instead of resolving | S2 → A2 chat | floor applied in the orchestrator, then the same two paths |

Design decisions worth reviewing:

* **The keyword screen is the floor, not a classifier.** `agents/a1/crisis-keywords.ts` already
  existed (E17-S6) and says of itself that it must never be treated as a classifier. It is used here
  only in the failure branch, where it can only ever *raise* the state, and the header comment now
  documents this third use. A real classification is never overridden by a keyword — asserted
  (`does not touch the classifier's verdict when the model does answer`).
* **A2 is skipped, not "run at S2".** If risk was never assessed, a model-generated therapeutic reply
  is exactly what must not go out; A9-post cannot gate it either, because it has no A1 state to gate
  against. This is a deliberate contract change and two pre-existing tests were rewritten to it
  (`orchestrator.test.ts`, `orchestrator.testMode.test.ts`), with comments saying so.
* **Every degraded path carries machine-readable code**, mirroring E17-S6's `budget` precedent:
  `AGENT_TURN.safety` / `CRISIS_SIGNAL.safety` = `{ code, reason, crisis_floor? }` on the wire, and
  `PipelineResult.safety` in-process. `reason` is `llm_timeout | llm_throttled | llm_api_error |
  llm_parse_failure | llm_exception` — never message text.
* **New governed copy** in `pipeline/fallbacks.ts`: `SAFETY_UNAVAILABLE_RESPONSE`,
  `MODEL_UNAVAILABLE_RESPONSE`. Both hold the thread, ask nothing diagnostic, and name the approved
  helplines (the same set as `CRISIS_RESPONSE` / `BUDGET_PAUSED_RESPONSE`). Clinical sign-off on the
  words is still open — same open item the file already records.
* **Worker parity** (E17-S1 §7 gap 1): `apps/worker/src/lib/bedrock.ts` now returns
  `SAFE_FALLBACK` + `fallbackUsed: true` on a thrown call **and** on an empty candidate, instead of
  `''`; `failureKind` travels with it. The worker duplicates `llm-failure.ts` for the same reason it
  duplicates `llm-types.ts` (separate deployable, shared packages only) — documented in-file.

## 4. The audit chain (new, ported from the reference core)

| Piece | File |
| --- | --- |
| Hash construction, canonical JSON, `AuditChain`, `verifyAuditChain` | `apps/api/src/lib/audit-chain.ts` |
| Durable store over `model AuditEvent` (append with head-race retry, verify) | `apps/api/src/lib/audit-log.ts` |
| `GET /audit/verify` | `apps/api/src/routes/audit.ts` |
| Schema + additive migration | `packages/prisma/schema.prisma`, `packages/prisma/migrations/20261028193000_add_audit_chain/migration.sql` |
| Wiring (one row per turned served, plus crisis rows) | `apps/api/src/pipeline/orchestrator.ts` |

`hash = sha256(prev_hash + canonical_json(body))`, `GENESIS = '0'×64`, `seq` contiguous from 1 —
byte-identical to `reference/python-core/okuvu/audit.py`:

```
$ python3 /opt/data/cache/scratch/e17s4/make_py_chain.py     # reference impl writes a 3-event chain
python verify: (True, None)
python events: 3 head: c4cfa6170281ebaf001f24edc0987874f30ce0a339385982d69037c90c881d1c

# TypeScript verifier over that Python-produced chain:
TS_VERIFIES_PY {"ok":true,"count":3,"firstBadSeq":null,"head":"c4cfa6170281ebaf001f24edc0987874f30ce0a339385982d69037c90c881d1c"}

# …and the reverse: the Python verifier over a chain the TypeScript chain wrote
python verifies TS chain: (True, None) | count: 2
python head: 3c89a6ac7be206f1ff83e984a4d3a5d25d35b31d3cad3922359d5794b3fa8292
python verifies tampered TS chain: (False, 1)
```

Same head hash in both directions, and both verifiers catch an edited detail. (These two scripts are
throwaway probes in the scratch dir, not committed — the reference core is not in this repo, so a
permanent test would have nothing to run against.)

Storage choices that matter: the sealed bytes are stored as **text** (`body`), not `jsonb`, because
jsonb reorders keys and rewrites numbers — the bytes that were sealed must be the bytes that are
verified. `prev_hash` is UNIQUE, so two concurrent appends cannot fork the chain (the loser gets a
unique violation and re-reads the head); appends are also serialised in-process. Queryable columns
(`actor`, `action`, `object`, `at`, `prev_hash`) must agree with the sealed body or verification
fails, so editing a column alone is caught.

`GET /audit/verify` returns `{ok, count, first_bad_seq, head}`, **200** when the chain verifies and
**500** when it does not (a probe that only reads status codes must not see a tampered chain as
healthy). It is JWT-gated like every other non-health route (E17-S3 §2).

An audit append that fails does **not** fail the turn: it logs `audit_append_failed` and the turn is
served. The alternative would convert a served safety path into exactly the generic error this story
removes. That trade-off is documented at the call site.

## 7. Not done / not verified

1. **No deploy, no build trigger, no `terraform apply`, no service change, no `plan/run-ledger.psv`
   edit.** Live behaviour is the orchestrator's to verify; nothing here claims it.
2. **The migration was not applied to any database.** There is no Postgres in this environment and
   no shadow database, so `prisma migrate diff` could not be used to generate the SQL — it is
   hand-written to match `schema.prisma` (§4). `prisma generate` accepts the schema (it produced the
   `auditEvent` delegate the typecheck and tests use), but `prisma migrate deploy` against a real
   database is unverified. It is additive-only (one new table, no changes to existing ones).
3. **Chain persistence was proven against an in-memory delegate, not Postgres.** The delegate
   reproduces the migration's columns and both UNIQUE constraints (so the head-race retry is
   exercised), but real-Postgres behaviour — including whether `body` TEXT round-trips byte-identically
   through the pg driver — is unverified here. The scratch cross-check with the Python reference
   (§4) covers the hash construction, not the column type.
4. **`/audit/verify` was not called on a deployed task.** Locally it returned
   `{"ok":true,"count":2,…}` through the real Fastify route with `LOCAL_DEV_BYPASS_AUTH`; in a deploy
   it needs a Cognito token, and `count` will be 0 until that task has served a turn.
5. **No live Bedrock call.** The 429 is produced by an h2c stub chosen to match the real error shape
   (`x-amzn-ErrorType: ThrottlingException`); the real service was not called (no credentials, and
   E17-S2 already proved task-role access).
6. **Clinical sign-off on the new copy is still open** (`SAFETY_UNAVAILABLE_RESPONSE`,
   `MODEL_UNAVAILABLE_RESPONSE`) — same open item as `CRISIS_RESPONSE` and `BUDGET_PAUSED_RESPONSE`.
7. **The keyword screen's known false positive is unchanged and now matters slightly more**: a
   message like *"I could kill myself laughing"* will take the crisis path while the classifier is
   down. That is the documented, accepted trade in `crisis-keywords.ts` (one crisis card vs. a
   missed disclosure); it is recorded here because this story is what puts the screen on a
   user-facing failure path.
8. **Tail truncation of the chain is not detectable by `verify`** (deleting the newest rows leaves a
   shorter but internally valid chain) — the same property the reference implementation has. A head
   witness / external anchor is not built.
9. **A9-pre (governance) unreachability still resolves to `Restricted` and does not change the user's
   path.** Out of scope; unchanged.
10. **Mobile client untouched.** The new `safety` field on `AGENT_TURN`/`CRISIS_SIGNAL` is additive and
    ignorable; the Dart client needs no change to keep working, but no mobile test was run here.
11. **`apps/test-harness` was typechecked, not tested** — it imports the api's `generate-content` and
    `shared-types`, which this story touched.
