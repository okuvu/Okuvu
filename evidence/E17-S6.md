# E17-S6 — token and cost budgets enforced in the request path

Date: 2026-10-28 (UTC). Branch `feat/E17-S6-budgets`, worktree off `origin/develop`
(`7cdc769`). No deploy, no `terraform apply`, no ECS service touched, no dependency
changed, model and prompt copy untouched.

Acceptance: *"A per-session and a per-day budget are enforced in the request path;
exceeding either returns the budget message rather than an unhandled error; measured
cost per session is recorded from real usage logs."*

---

## 1. Where the budget lives — decided from the code, not from preference

There is exactly one path that spends model tokens on behalf of a user, and it is in
`apps/api`:

| Path | Evidence |
| --- | --- |
| Chat turn over WebSocket | `apps/api/src/routes/websocket.ts:169` (`USER_TURN`) → `pipeline/orchestrator.ts:57` `processTurn` → A1/A9-pre/A2/A9-post → `lib/generate-content.ts` → `lib/bedrock.ts:344` `ConverseCommand` |
| Journal prompt over HTTP | `apps/api/src/routes/journal.ts:139` `POST /journal/prompt` → `agents/journal-prompt/agent.ts:15` → same `generateContent` |

The worker does **not** run turns. `apps/worker/src/routes/` contains `summary.ts`,
`beta-retention.ts`, `cleanup.ts`, `health.ts` and there is no `processTurn` / chat
route in `apps/worker/src` (grep: `processTurn` appears only in `apps/api` and
`apps/test-harness`). Worker Converse calls are SQS-triggered post-session summary and
memory jobs: no user is waiting, and there is no session to attribute them to — a
per-session budget there would have nothing to count against. So the budget is enforced
in the api, at the two user-initiated call sites, and the worker's spend is a recorded
gap (§9), not an oversight.

**Enforced before the first model call**, so a refused turn cannot half-run and cannot
cost anything: `websocket.ts:245-249` (gate) then `:304` (metered turn);
`journal.ts:160` (gate) then `:179` (metered call).

## 2. Budgets, counters, and where they persist

`apps/api/src/lib/token-budget.ts` (new) — one module, both budgets:

| | Limit | Key | TTL |
| --- | --- | --- | --- |
| per session | tokens (input + output, as Converse reports them) | `okuvu:budget:v1:session:<sessionId>:tokens` | 24 h |
| per session (recorded cost) | — (measurement, not a limit) | `okuvu:budget:v1:session:<sessionId>:microusd` | 24 h |
| per day | measured list-price USD, per authenticated subject, UTC day | `okuvu:budget:v1:day:<uid>:<YYYY-MM-DD>:microusd` | day end + 1 h |

* Defaults: `SESSION_TOKEN_BUDGET=500000`, `DAILY_COST_BUDGET_USD=0.75`
  (`token-budget.ts:60-61`), both override-able by env with no code change and no
  terraform edit required (`.env.example` documents them). Missing/unparseable values
  fall back to the default — never to `0` (which would refuse every turn) or `NaN`
  (which would never refuse one): `resolveBudgetConfig`, `token-budget.ts:105`.
* Reused rather than reinvented: the same Redis singleton the repo already has
  (`lib/redis.ts`, shared with `lib/rate-limit.ts` and `@fastify/rate-limit`), the same
  `REDIS_URL` the ECS task definition already injects, `ioredis` pipelines, and the
  existing per-user identity (`request.user.uid`) the rate limiter keys on.
* Cost is stored as **integer micro-USD**, so thousands of additions cannot drift into
  "spent 0.999999 of 1.0" (`costMicroUsdForUsage`, `:126`).

**Redis-unavailable behaviour.** Counting is authoritative in Redis when it is there
(holds across ECS tasks). Without `REDIS_URL` — or on a Redis error — it degrades to a
**per-process** in-memory counter (`readCountersFromStore` / `addCountersToStore`,
`:222-289`) and logs `budget_counter_store` once per process.

Why that direction: `lib/rate-limit.ts` deliberately fails **open** (a Redis outage
must not take the product down) — that is right for a rate limit, which protects
availability. A cost budget protects money, so "unlimited until Redis returns" is the
wrong degradation; but "refuse every turn because Redis is down" is worse, because it
turns an infrastructure fault into a mental-health product outage. Per-process counters
are the middle: still bounded (with N api tasks the effective day ceiling is at most
N × the configured value), never blocked by infrastructure, and visible in one log line.
`token-budget.test.ts` pins all three cases: Redis present, Redis absent (still refuses
at the boundary), Redis throwing on read and on write (still counts, still refuses).

## 3. Refusals — codes, statuses, and what the user actually sees

| Code | Status | Condition |
| --- | --- | --- |
| `BUDGET_EXCEEDED_SESSION` | 429 | session's measured tokens ≥ `SESSION_TOKEN_BUDGET` |
| `BUDGET_EXCEEDED_DAY` | 429 | day's measured cost ≥ `DAILY_COST_BUDGET_USD` |

* Boundary rule: `used >= limit` refuses (`checkBudget`, `:402`). A budget exactly
  spent has no headroom, which is also what "at budget boundary" asserts in the tests.
* **WebSocket turn** — a refusal is *not* an `ERROR` frame. The deployed client renders
  `AGENT_TURN.message` as an assistant message and silently drops `ERROR` frames
  (`apps/mobile/lib/src/core/websocket_service.dart:158` only debug-prints), so an
  `ERROR`-only refusal would show the user **nothing**. The refusal therefore rides
  `AGENT_TURN` with the governed copy in `message` and the structured notice in
  `payload.budget` (`BudgetNotice` in `packages/shared-types/index.ts:139`;
  `websocket.ts:253-282`). No `ERROR` frame is emitted — asserted in
  `websocket-budget.test.ts`.
* **Journal prompt** — real HTTP: `429` with
  `{ error: { code, message, used, limits, retry_after_seconds } }` (`journal.ts:160-176`).
* User-facing copy is a governed constant, not an error string:
  `BUDGET_PAUSED_RESPONSE` in `pipeline/fallbacks.ts:58-73` — holds the thread,
  explains no machinery, and names the helplines. It is not `TURN_FAILED`, not a 500, not
  silence.
* No path can produce an unhandled rejection: the gate's own failures are caught and
  logged in `websocket.ts:245-251` (an accounting bug must not drop a therapy message);
  refusals are ordinary return values, and the journal route returns a reply.

### The crisis path is not blockable

`admitTurn` (`token-budget.ts:473`) is the single decision point, and it has exactly one
override: if the message matches explicit S4 language, an over-budget turn runs anyway
(`crisis_bypass`). The screen is a regex with no model call
(`agents/a1/crisis-keywords.ts`), it is the same list A1's canned classifier now uses
(`agents/a1/agent.ts:50-56` — one list, not two), and every admitted turn still goes
through A1's real classification, so the bypass changes cost, not safety. The tradeoff
is stated plainly: a user can spend one turn by typing a crisis phrase. That is the
cheaper error by orders of magnitude — the alternative is refusing a disclosure of
intent to die in order to protect a cost ceiling. Each bypass logs
`event:"budget_bypass"` so it is countable.

For non-crisis turns the refusal is still a safe response, not a degraded one: the
governed copy carries the helplines, so a user arriving in distress at an exhausted
budget is signposted even though the model is not called.

## 4. How cost is measured (no estimates anywhere)

1. `lib/bedrock.ts:353` reads `response.usage` from the Converse response and narrows it
   with `toTokenUsage` (`:289`) — `inputTokens`/`outputTokens` are the service's own
   counts, `totalTokens` is derived so the two can never disagree. A billed-but-empty
   candidate (`stopReason: max_tokens`, no content) is metered too: it was charged for.
2. `GenerateContentResult.usage` (`lib/llm-types.ts`) carries them out; the OpenRouter
   path maps `usage.prompt_tokens`/`completion_tokens` the same way (`lib/openrouter.ts`).
3. `recordModelUsage` (`token-budget.ts:565`) accumulates them into an async-local
   per-turn meter, so all of a turn's calls (A1, A9-pre, A2, A9-post) are summed without
   changing any agent's signature. `withUsageMetering` (`:599`) persists the measured
   total after the turn — including when the turn throws — and logs
   `event:"budget_usage"` with `input_tokens`, `output_tokens`, `turn_cost_usd`,
   `session_cost_usd`, `session_tokens`, `day_cost_usd`, `counter_store`.
4. Pricing: ap-south-1 list price for `qwen.qwen3-32b-v1:0`, input **$0.00018 / 1K**,
   output **$0.00071 / 1K** (`token-budget.ts:48-49`), input and output priced
   separately.

## 9. Not done / known gaps (blunt)

1. **Worker spend is not metered.** SQS summary/memory jobs call Converse too; they are
   outside the per-session/per-user request path and have no session to charge. A
   tenant-wide cap needs its own story.
2. **Embedding calls (`InvokeModel`) are not metered** — only Converse. First-turn RAG
   retrieval embeds a query; that spend is invisible to these counters.
3. **Refused turns are not persisted.** A budget refusal is answered but leaves no
   `Turn` row, so the user's message is not in the transcript. Doing that properly means
   reusing the orchestrator's turn-writing transaction, not duplicating it in the route.
4. **No live end-to-end turn against the deployed API** (auth + deploy, §7).
5. **No terraform wiring** for the two env vars: defaults are sufficient, and the brief
   allowed terraform only with a shown plan, which needs a backend this worktree does not
   have.
6. **Session budget is per `SessionLog` id**, so a client that opens a new session gets a
   fresh session budget — the per-day cost budget is the backstop for that, which is why
   both exist.
7. **Crisis bypass is exploitable for one turn per attempt** (§3) — deliberate, and
   logged, not hidden.
8. The A2 "no S-07 JSON block found in LLM response" log line seen during the live probe
   is pre-existing behaviour of A2's parser, not something this story touched.
