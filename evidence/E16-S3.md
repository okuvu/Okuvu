# E16-S3 — Production Cognito pool with real therapist accounts

Story: *"A therapist logs in at https://okuvu.in with a real Cognito user and reaches the
portal dashboard; three seed therapist accounts exist with distinct passwords held in SSM;
no shared demo credential is reachable from the login page."*

Scope honoured: worktree only. **No `terraform apply`/`destroy`**, no CodeBuild build, no ECS
service touched. Terraform changes are written and planned against a *copy* of the state in the
worktree; the orchestrator applies. Real (non-terraform) writes performed: three Cognito users,
three SSM SecureString parameters — both explicitly in scope for this story.

All timestamps UTC. Base: `origin/feat/chat-voice-input`. Worktree:
`/opt/data/cache/scratch/wt-E16-S3`. Branch: `feat/E16-S3-cognito`.

### 1.3 The actual defect: sign-in was impossible, not just demo-flavoured

A pool without a domain still publishes a discovery document, but its `authorization_endpoint`
points at the `cognito-idp` host, which does not implement the OAuth redirect endpoint.
Clicking the deployed login button therefore ended here:

```
$ curl -s -o /dev/null -w "HTTP %{http_code}\n" \
  "https://cognito-idp.ap-south-1.amazonaws.com/ap-south-1_eaJaK7g4g/authorize?client_id=...&response_type=code&..."
HTTP 400
{"code":"BadRequest","message":"The server did not understand the operation that was requested.","type":"client"}
```

and in a real browser at https://portal.okuvu.in/auth, the button redirects to
`https://cognito-idp.ap-south-1.amazonaws.com/ap-south-1_eaJaK7g4g/authorize?...` and renders that
raw JSON body. So before this change: **one dead sign-in button, zero users in the pool, no way
in** — with or without a "demo" account.

### 1.4 Demo-credential audit — result: no shared credential exists, but a bypass does

Searched (`apps/`, `packages/`, `scripts/`, `infrastructure/`, `docs/`, plus full git history for
`demo@`, `Demo123`): no `CredentialsProvider`, no `providers/credentials`, no hardcoded password
in any `.ts`/`.tsx` under `apps/therapist-portal/src`, no seeded password anywhere
(`src/scripts/seed-therapist.ts` writes a DB row only — email, no password). The login UI shows
one button and no credential text. **There is no shared demo login to remove.**

What does exist is a dev-only auth bypass, env-gated in four places:

- `src/lib/auth.ts:40` — `signIn` callback returns `true` without a DB lookup
- `src/lib/auth.ts:86-88` — `auth()` returns a synthetic session `bypass@okuvu.dev`
- `src/proxy.ts:15-17` — route guard skipped
- `src/server/trpc.ts:13` — tRPC context substitutes a mock session

It is not reachable in this deployment: `instrumentation.ts:17` refuses to boot when
`NODE_ENV=production` and `LOCAL_DEV_BYPASS_AUTH=true`, and the running task definition
(`evia-beta-portal:6`) carries no `LOCAL_DEV_BYPASS_AUTH` key at all (full env inspected:
`NODE_ENV=production`, `AWS_REGION`, `PORT`, `HOSTNAME`, `COGNITO_ISSUER`,
`COGNITO_THERAPIST_POOL_ID`, `COGNITO_THERAPIST_CLIENT_ID`, `COGNITO_REGION`,
`NEXTAUTH_URL`, `ADMIN_EMAILS`, `NEXT_TELEMETRY_DISABLED`, `BREVO_FROM_*`). It is a bypass, not a
credential — left as-is (local dev workflow), covered by the new test asserting the provider list
is `['cognito']` or empty and never contains `credentials`.

Two staler artefacts fixed in passing: `docs/therapist-onboarding/therapist-seed-guide.md`
claimed Google OAuth + Firebase phone OTP as the auth paths, and the login copy promised a
one-time code that an unenrolled (MFA-optional) account never gets.

## 2. Terraform changes — written, planned, **NOT applied**

### 2.1 Diff summary

`infrastructure/aws/evia-beta/cognito.tf`
- **New** `aws_cognito_user_pool_domain.therapists` — prefix domain
  `okuvu-therapists` → `https://okuvu-therapists.auth.ap-south-1.amazoncognito.com`. This is the
  fix for §1.3: it is what gives the pool working `/oauth2/authorize` and `/oauth2/token`.
- New `locals`: `portal_public_hostnames` = `portal.okuvu.in` + `portal_alias_hostnames`;
  callback/logout URLs derived per host (`https://<host>/api/auth/callback/cognito`,
  `https://<host>/auth`) plus the existing localhost dev URLs.
- `aws_cognito_user_pool_client.portal`: callbacks/logout now include **okuvu.in** and
  **www.okuvu.in**; `explicit_auth_flows` drops `ALLOW_USER_SRP_AUTH` (public-client flow,
  unused) and adds `ALLOW_ADMIN_USER_PASSWORD_AUTH` (IAM-gated, used by the verification script);
  `allowed_oauth_flows` stays `["code"]` — **no implicit grant**.
- `password_policy.password_history_size = 5` (rotation cannot reuse the last five).

`infrastructure/aws/evia-beta/portal.tf`
- Task env: `NEXTAUTH_URL` (pinned to `https://portal.okuvu.in`) replaced by
  `AUTH_TRUST_HOST=true` unless `var.portal_nextauth_url` pins an origin. Reason: one deployment
  must complete the OAuth round-trip on all three hostnames; next-auth v4 honours
  `AUTH_TRUST_HOST` (`node_modules/next-auth/utils/detect-origin.js:9-11`) and then derives the
  origin from `X-Forwarded-Host`. A forged `Host` cannot help an attacker: an unregistered origin
  produces a `redirect_uri` Cognito rejects.
- Portal ALB host rules (`portal_https`, `portal_http`) match `local.portal_public_hostnames`
  instead of `var.portal_hostname` only — so `okuvu.in` and `www.okuvu.in` reach the portal, not
  the API default target. The ACM cert already carries `okuvu.in` and `www.okuvu.in`
  (`dns.tf:46-52`), so no certificate change is needed.

`variables.tf` — new `portal_alias_hostnames` (default `["okuvu.in","www.okuvu.in"]`),
`portal_nextauth_url` (default `""`), `cognito_therapist_domain_prefix` (default
`okuvu-therapists`), each validated; `portal_callback_urls`/`portal_logout_urls` descriptions
updated.
`outputs.tf` — new `cognito_therapist_hosted_domain`.

## 3. Seed therapist accounts

`scripts/provision-therapists.mjs` (new) — idempotent operator path, AWS CLI based:

1. reads `/evia-beta/therapists/<slug>/password` (`ssm get-parameter --with-decryption`);
   generates a 32-character password satisfying the pool policy (one of each class, shuffled)
   and stores it as **SecureString** only if absent;
2. `admin-create-user` (email as username, `email_verified=true`, `--message-action SUPPRESS`)
   then `admin-set-user-password --permanent` → status `CONFIRMED` immediately;
3. leaves an existing `CONFIRMED` user untouched unless `--rotate`;
4. optionally upserts the `Therapist` allowlist row when `DATABASE_URL` is set;
5. `--verify` authenticates each credential against the real pool and prints **claims only**.

Secret hygiene: every call that carries a password (`ssm put-parameter`,
`cognito-idp admin-set-user-password`, `cognito-idp initiate-auth`) is passed with
`--cli-input-json file://…` from a `0600` file in a private temp dir, deleted in `finally` — the
password never appears in `argv` (`ps`), shell history, stdout, the JSON report or the repo.

```
$ node scripts/provision-therapists.mjs --dry-run
ananya.rao@okuvu.in      would-create (ABSENT)
rohan.mehta@okuvu.in     would-create (ABSENT)
priya.nair@okuvu.in      would-create (ABSENT)

$ node scripts/provision-therapists.mjs
ananya.rao@okuvu.in      created (CONFIRMED)
rohan.mehta@okuvu.in     created (CONFIRMED)
priya.nair@okuvu.in      created (CONFIRMED)

$ node scripts/provision-therapists.mjs --verify
ananya.rao@okuvu.in      unchanged (CONFIRMED)      # idempotent: no password reset

priya.nair@okuvu.in      unchanged (CONFIRMED)
ananya.rao@okuvu.in      authenticated
rohan.mehta@okuvu.in     authenticated

       "iss":"https://cognito-idp.ap-south-1.amazonaws.com/ap-south-1_eaJaK7g4g"} , ...]
```

### 7.2 Seed the allowlist rows (required before "reaches the dashboard")

Cognito identity alone is not enough: `auth.ts` requires a `Therapist` row with the same email.
RDS is `publicly_accessible = false`, so this has to run from inside the VPC (or anywhere that can
reach the DB):

```bash
DATABASE_URL=$(aws secretsmanager get-secret-value --secret-id evia-beta/database \
  --query SecretString --output text | jq -r .database_url)
DATABASE_URL="$DATABASE_URL" node scripts/provision-therapists.mjs   # step 4 upserts the rows
```

Without `DATABASE_URL` the script prints the equivalent manual command
(`npx tsx src/scripts/seed-therapists-batch.ts ananya.rao@okuvu.in rohan.mehta@okuvu.in priya.nair@okuvu.in`
from `apps/therapist-portal`). Skipping this yields a correct Cognito sign-in followed by
`?error=unauthorized` — the allowlist doing its job.
