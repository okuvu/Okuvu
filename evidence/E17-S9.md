## 2. Shape chosen: (b) deterministic floor — and why not (a) a prompt version

Two shapes were on the table. I chose **(b), a deterministic medical-emergency floor**, and did
**not** ship a2-okuvu-v2.2.txt. Reasons, in order of weight:

1. **The criterion is a property of the delivered text, and a prompt cannot promise it.** "112 in
   the first sentence" has to hold for the text the user receives. With a prompt branch, that text
   is model output behind three failure modes that already exist in this codebase: the model can be
   throttled/timed out (`lib/bedrock.ts` → `SAFE_FALLBACK`, `pipeline/fallbacks.ts`
   `MODEL_UNAVAILABLE_RESPONSE`), A9-post can return `BLOCKED` and substitute
   `getSafeFallback()` (`orchestrator.ts` A9-post branch), and a 32B model at temperature 0 is
   compliant-most-of-the-time, not deterministically compliant. 100% at pipeline level is only
   achievable if no model writes the sentence. The floor is the same tier as the existing crisis
   card and S3 grounding reply: static approved copy, persisted turn, no A2 call, no A9-post review
   of text no model wrote.
2. **Fewer false positives than the alternative, not more.** A prompt branch is applied to *every*
   S0–S2 turn, so its false-positive surface is the model's judgement on all traffic. The floor only
   fires on an explicit, enumerated set of presentations, each of which requires either a single
   unambiguous phrase ("unconscious", "bleeding won't stop") or a co-occurrence that anxiety
   messages do not produce ("chest pain" **with** a numb/radiating arm; "fever" **with** confusion or
   an inability to keep water down; "heavy bleeding" **with** pregnancy or injury). §4 is the proven
   negative list.
3. **Least new surface, and none of it model-visible.** A prompt bump changes every response path in
   the product, forces a full eval-gate re-run and re-baseline of all six gold-set categories, and
   touches 331 crisis tests' shared fixture (the A2 system prompt). The floor touches one screen
   module, one router rule, one orchestrator branch, two copy constants. All 1,248 existing tests
   passed unmodified on the first run (no test's expectations had to be changed — see §7).
4. **It also covers the classifier being down.** If Bedrock throttles, the base pipeline served
   `SAFETY_UNAVAILABLE_RESPONSE` (helplines, no 112) for a message describing a heart attack. The
   floor is message-driven and runs before that branch, so a medical emergency gets 112 even on the
   turn where the classifier never answered. A prompt branch cannot do that at all.

What (b) cannot do, stated plainly: it does not recognise paraphrases outside its patterns ("my dad
collapsed at the table and won't get up" is caught by *unresponsive/won't wake*, but "his face looks
wrong and he can't hold his cup" is not). That long tail is what a prompt branch *is* good for, and
it is the recommended follow-up in §11, to be judged by the eval gate rather than by this story.

## 3. The copy — for clinical sign-off under E17-S7

Two constants, both in `apps/api/src/pipeline/fallbacks.ts`, nothing else anywhere. This is the
exact text a user receives; the evidence file reproduces it so it can be reviewed without opening
code.

### 3.1 `MEDICAL_EMERGENCY_RESPONSE` — the ordinary case (no self-harm wording)

> Please call 112 for emergency medical help right now — that is the ambulance and emergency number
> in India, and they can send help to you. What you've described is a medical emergency, so please
> don't wait for me on this one: make the call first, and put it on speaker if you can. I'm here, and
> I'll stay with you while you do.

### 3.2 `MEDICAL_EMERGENCY_CRISIS_RESPONSE` — the overlap case (A1 also returned S4, or flagged crisis language, on a medical message)

> Please call 112 for emergency medical help right now — that is the ambulance and emergency number
> in India, and they can send help to you. I can also hear that there is more than the physical side
> to this, and I don't want you to carry that alone: once you've called, please reach out to iCall on
> 9152987821 or the Vandrevala Foundation on 1860-2662-345. I'm here, and I'll stay with you.

Notes for the reviewer:

- **First sentence is identical in both.** One sentence, one number, one instruction — that is the
  sentence the acceptance criterion is about, and it is the same sentence in both variants.
- **112 is India's single emergency number** (police/fire/ambulance) and is already the number the
  crisis path lists as "Emergency Services: 112" (`CRISIS_RESPONSE`). No new number is introduced
  except the two mental-health helplines in 3.2, which are the pre-existing approved set (iCall
  9152987821, Vandrevala 1860-2662-345) already used by `CRISIS_RESPONSE`, `BUDGET_PAUSED_RESPONSE`
  and `SAFETY_UNAVAILABLE_RESPONSE`.
- **No diagnosis, no dosing, no first-aid procedure, no outcome promise, no claim of clinical
  review.** No third-party attribution is implied ("they can send help to you" is a statement about
  112, not a promise of outcome). Copy says nothing about what is wrong with the user.
- **No reassurance in place of care.** Deliberately absent: "probably anxiety", "you'll be fine",
  "don't worry", "it's normal", "just wait", "nothing to worry about" — the exact classes the gold
  set forbids (`must_not_include`, me-01…me-05).
- **Works for first-person and third-person.** "What you've described" and "put it on speaker if you
  can" read correctly whether the user is the patient or is with one; the copy asks the user to do
  nothing clinical, so it cannot mislead an untrained bystander into a harmful intervention.
- **Thread is held.** It does not abandon the user ("I'm here, and I'll stay with you while you do"),
  but it does not invite further chat before the call — the call comes first by design.
- Wording to challenge in review, flagged by me rather than hidden: (i) "put it on speaker if you
  can" — advice about hands-free use, not clinical; drop it if the clinical owner prefers; (ii) 3.2's
  "more than the physical side to this" is the one interpretive phrase in either constant, and it is
  the phrase most worth a clinician's eye; (iii) neither constant mentions the user's therapist,
  deliberately — a therapist cannot answer an ambulance call.

## 4. The screen, and what it deliberately does **not** match

`apps/api/src/agents/a1/medical-emergency-keywords.ts`. Not a classifier, same disclaimer as
`crisis-keywords.ts`: no context, negation or idiom handling. It matches by presentation:

| presentation | rule | why that shape |
| --- | --- | --- |
| chest pain | `CHEST_PAIN` **and** `CHEST_PAIN_RADIATION` (left arm / numb / jaw / radiating / between shoulder blades) | chest tightness + racing heart is how this product's users describe a panic attack; only radiation/numbness distinguishes the ischaemic picture |
| unconscious / unrousable | single phrase: `unconscious`, `unresponsive`, `not responding`, `won't wake`, `no pulse` | unambiguous |
| breathing failure | `not breathing`, `stopped breathing`, `choking`, `turning blue` | **`can't breathe` alone is excluded on purpose** — it is the single most common panic phrasing in this app |
| uncontrolled bleeding | `bleeding won't stop`, `can't stop the bleeding`, `blood pouring/spurting`, `soaking through`, `soaked in blood` | "the user has already failed to stop it" is the signal, not the volume |
| heavy bleeding | `HEAVY_BLEEDING` **and** `BLEEDING_CONTEXT` (pregnant / miscarriage / gave birth / cut / wound / glass / knife / accident / soaking / clots) | heavy period bleeding must stay with A2 |
| fever | `FEVER` **and** `FEVER_DANGER_SIGN` (confusion, delirium, can't keep water/fluids down, stiff neck, rash, seizure, unresponsive) | 104°F alone is not an emergency; 104°F with confusion is |
| stroke | face droop, slurred speech, one-sided weakness/numbness, "having a stroke" | high specificity |
| seizure | "having a seizure", "keeps having seizures", "convulsing" | bare "fitting" excluded (ambiguous) |
| ingestion | "drank/swallowed/took a (whole) bottle/pack/strip of", poison, bleach, phenyl, pesticide, kerosene | covers the me-02 form and poisoning |
| major trauma | snake bite, electric shock, drowning, stabbed, road accident, hit by a car/bike, head injury, fell from a height | India-relevant, unambiguous |
| airway swelling | throat closing/swelling, can't swallow, anaphylaxis, severe allergic reaction | unambiguous |

**The self-harm guard is the safety-critical piece.** `hasMedicalEmergencyLanguage()` calls
`hasSelfHarmLanguage()` **first** and returns false on a match. That guard is
`hasCrisisLanguage()` (the existing S4 screen — still the authority, not duplicated) plus an explicit
extension for the forms a medical sentence is most likely to hide: `cut myself`, `cut my wrists`,
`slit my…`, `overdose(d)`, `took too many pills`, `kill myself`, `suicid*`, `want to die`,
`don't want to live`, `better off dead/without me`, and the Hinglish `khud ko khatam` /
`marna chahta` / `jeena nahi`. Adding phrases there only ever makes the medical floor *more*
conservative; it cannot cause a missed crisis because S4 detection is untouched by it.

### Proven negatives (committed as tests, `ORDINARY_DISTRESS` in the suite)

Fifteen everyday distress messages that must **not** produce an ambulance instruction. All are
asserted `false` in `src/__tests__/medical-emergency.test.ts`:

```
"I'm having a panic attack, my chest is tight and my heart is racing"      → no match
"I feel like I can't breathe when I get anxious"                            → no match
"I feel like I'm going to have a heart attack when I panic"                 → no match
"I'm on my period and bleeding heavily with bad cramps"                     → no match  (no pregnancy/trauma context)
"I've had a fever of 101 last night but I'm okay now"                       → no match
"I've had a fever of 104 for two days"                                      → no match  (no danger sign)
"I cut my finger while cooking, it's a small cut"                           → no match
"I feel sick to my stomach about my exam tomorrow"                          → no match
"I'm so scared about my results. My parents will kill me."                   → no match
"I feel low today and I could not get out of bed"                           → no match
"my therapist cancelled again and I am annoyed"                             → no match
"I passed out at a party last year and it was so embarrassing"               → no match  ('passed out' excluded as a phrase)
"I have a headache and I'm tired"                                           → no match
"I'm 8 weeks pregnant and a bit spotting"                                   → no match
"everyone would be better off without me"                                   → no match
```

And five self-harm messages that must stay off the medical floor (asserted
`hasSelfHarmLanguage === true` **and** `hasMedicalEmergencyLanguage === false`):

```
"I want to die"
"I cut my wrists and the bleeding won't stop"
"I took a whole bottle of pills to kill myself"
"I have been cutting myself again and there is a lot of blood"
"khud ko khatam kar lunga"
```

The residual false-positive risk is stated rather than engineered away: "I'm bleeding heavily and I
feel dizzy" does not match (no pregnancy/trauma context word), "my chest hurts and I'm sweating"
does not match (sweating excluded as a panic symptom). Both are misses, not false positives — the
direction that keeps a distressed person with a chat reply rather than sending them an ambulance
number, which is the trade this story chose on purpose.

## 5. Precedence — how the crisis path is kept intact

`routeTurn()` (`apps/api/src/agents/a8-router.ts`) now checks the medical screen **before** S4 and
before governance. That ordering is deliberate and tested; the reasons:

- An explicit self-harm disclosure is never a medical match (the guard in §4), so S4 disclosures
  still return `{agent:'crisis'}` and still get `CRISIS_RESPONSE`. Two tests pin this: `I want to
  die` → crisis, and `I want to die. I cut my wrist and the bleeding won't stop.` → crisis.
- The case the ordering actually fixes is me-04: A1 reads an accidental injury ("I cut my hand badly
  on broken glass") as *active self-harm* and returns S4. A model-generated S4 on an injury is not a
  disclosure, and an ambulance is the correct answer to it.
- When A1 *does* return S4 on a medical message (or flags `crisis_language_detected`), the
  orchestrator serves `MEDICAL_EMERGENCY_CRISIS_RESPONSE` — 112 first, then the crisis helplines —
  and sets `SessionLog.crisis_flag_detected`. Nothing is withdrawn from that user; the ambulance
  number is simply not displaced by the mental-health card.
- Governance can no longer pre-empt a medical emergency: a `Blocked` A9-pre verdict on a message
  describing an unconscious relative used to serve the static policy-boundary line. The medical
  screen is checked first (tested).

Unchanged and re-verified by the existing suites: S4 → crisis, S3 → deterministic grounding,
`Blocked` at S0–S2 → A2 `blocked`, and — with no `message` passed — every pre-E17-S9 routing rule
returns exactly what it returned before (a 9-case table in the new suite).

## 11. Residuals and follow-ups (not done here, on purpose)

1. **Prompt branch for the paraphrase tail (recommended, separate story).** The floor only recognises
   enumerated presentations. A `a2-okuvu-v2.2.txt` §6.1 ("if what they describe is a physical
   emergency, name 112 in the first sentence and do not route to the mental-health crisis card") would
   catch paraphrases the screen misses, and should be judged by the gate, not by this file. It changes
   every S0–S2 reply, so it needs its own run series.
2. **Mobile affordance.** The reply is plain text. A tappable "Call 112" on a turn carrying
   `safety.code = 'MEDICAL_EMERGENCY_FLOOR'` is a client story; the code is already on the wire for it.
3. **The dark v2 pipeline** (`apps/api/src/pipeline/v2/turn.ts`, behind `OKUVU_AGENT_PIPELINE_V2`,
   not wired to any route) has no medical branch. If that flag is ever turned on, this floor has to be
   added there first — recorded here so nobody discovers it at the flag flip.
4. **Overdose language defers to crisis on purpose.** "I took a whole bottle of pills" matches the
   self-harm guard, so it reaches the crisis card, whose helpline list includes Emergency Services 112.
   That is the crisis path being preserved, not an oversight — but a clinician may prefer an
   ambulance-first variant for ingestion, which is a copy decision for E17-S7.
5. **The crisis card itself still leads with mental-health helplines** for a self-inflicted injury
   with severe bleeding ("I cut my wrists and the bleeding won't stop" → crisis card, 112 listed but
   not first). Changing `CRISIS_RESPONSE` is a change to the approved crisis copy with 331 tests
   behind it — explicitly out of scope for this story, and flagged for E17-S7.
6. **No live/HTTPS verification.** No deploy and no `terraform apply` were run, per the story's hard
   rules; behaviour is proven by the real `processTurn` under test with only the model and the
   database stubbed, plus the base-commit router execution in §1.
