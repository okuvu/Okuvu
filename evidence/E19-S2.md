## 1. What was actually wrong

The portal has no `middleware.ts`; Next 16's proxy convention is `apps/therapist-portal/src/proxy.ts`. It redirected **every** unauthenticated request to `/auth` except `/auth`, `/api/auth*`, `/api/health`, `_next`, `/brand/*` and two icon paths. With no `/privacy` page and no exemption, an anonymous `GET /privacy` produced the 307 the orchestrator saw.

**The page had to be added, and the exemption had to be exact.** Making `/privacy` public by loosening the matcher or by prefix-matching `PUBLIC_*` would have opened the portal; the test in §4 pins that it does not.

Code changes (4 files modified, 3 added):

| File | Change |
|---|---|
| `apps/therapist-portal/src/app/privacy/page.tsx` | **new** — the policy page. Static server component, no session, no tRPC, no client hooks. |
| `apps/therapist-portal/src/proxy.ts` | **new `PUBLIC_PATHS = new Set(['/privacy'])`**, checked *before* `getServerSession`. `PUBLIC_ROUTES` (the `/auth` login page, which bounces signed-in users to `/`) is unchanged. |
| `apps/therapist-portal/src/__tests__/privacy-public-route.test.ts` | **new** — 7 tests: `/privacy` passes with no session lookup, signed-in users are not bounced, `/`, `/dashboard`, `/clients/abc`, `/api/trpc/*` still 307 to `/auth`, `/privacyx` and `/privacy/extra` are **not** exempt. |
| `apps/mobile/lib/src/config/app_config.dart` | `privacyPolicyUrl`: Google Docs "pub" link → `https://okuvu.in/privacy`. |
| `apps/mobile/test/config/app_config_test.dart` | test pinning that URL (it is a contract with Play, not an infra detail). |
| `apps/mobile/android/PLAY_RELEASE_CHECKLIST.md` | names the URL in the listing requirements (§1d) and marks hosting done (§4.4), leaving the Play Console field entry as an owner action. |
| `scripts/verify-privacy-route.sh` | **new** — re-runnable proof against localhost *or* the live host, exit 1 on failure. |

### Why the exemption is checked before `getServerSession`

A policy page is the one document that must render when everything else is broken. If the session lookup throws (Cognito unreachable, stale cookie, misconfigured provider) an unauthenticated visitor would get an error page on the privacy policy — exactly the failure Play reviewers see. Verified: `garbage` session cookie still returns 200 (§3), and the unit test asserts `getServerSession` is never called for `/privacy`.

## 6. What was NOT done / could not be verified

1. **The live 200 is unverified by me and unverifiable from here.** `https://okuvu.in/privacy` cannot serve this page until the branch is merged to `develop`, the portal image is rebuilt and deployed to `evia-beta-portal-tg`, and ECS rolls. Everything in §3 is a **local production build** (`next build` + `next start`) — the same artifact shape, not the deployed one. Post-merge, run `bash scripts/verify-privacy-route.sh https://okuvu.in`.
2. **TLS was not exercised.** Local runs are plain HTTP on `:3100`. The `https` leg is the ALB + ACM listener verified in E16-S1/E16-S2; this story adds a page behind it and does not touch certificates.
3. **No Play Console change was made.** The listing field is external state owned by a human; the repo carries the declaration and the checklist, not the live listing.
4. **No iOS listing material to update** (§5).
5. **Known product gaps documented, not fixed** (deliberately out of scope for a policy page, and flagged on the page itself):
   - account deletion does not remove journal entries, therapist notes, homework, reminders, appointments or the clinical access audit log (`apps/api/src/lib/account.ts`);
   - no automated retention/expiry exists for clinical records, so no retention period is published;
   - no named Grievance Officer is designated;
   - `TELEMETRY_ENDPOINT`/`CRASH_ENDPOINT` are unset, so analytics and crash reports never leave the device — the policy says this instead of describing shipping that does not happen.
6. **No legal review.** The page states its open questions and asserts no certification. Counsel still has to confirm: the transfer basis for platform speech recognisers and Brevo, the model provider's training-data position, the retention period, and the grievance-officer designation.
7. **Not touched, per instructions:** `plan/run-ledger.psv`, `terraform apply`, `develop`. Nothing was routed or re-routed. `evidence/E16-S2.md` was reported missing (§0), not recreated.
8. `apps/api/src/lib/email.ts` duplicates the Brevo integration; the portal copy is what the page describes. No behaviour change was needed there.
