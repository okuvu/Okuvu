Story acceptance criterion (verbatim): **"flutter build appbundle runs with the prod flavor and the
Cognito and FLAVOR dart-defines pointing at https://api.okuvu.in and exits 0; aapt2 reports package

## 1. The dart-define scheme already in the repo

No new mechanism was invented. `apps/mobile` reads three independent things at compile time:

| Define | Read in | Purpose |
|---|---|---|
| `FLAVOR` | `lib/src/config/app_config.dart:16` (`AppConfig.init`, throws `FlavorNotSpecifiedException` if empty) | selects `Environment.dev` / `beta` / `prod` |
| `COGNITO_REGION`, `COGNITO_USER_POOL_ID`, `COGNITO_CLIENT_ID` | `lib/src/config/cognito_config.dart:29-34` | Cognito client coordinates |
| `BASE_URL`, `WS_URL` (optional overrides) | `lib/src/config/app_config.dart:21-26` | override the flavour's base URL |

The prod flavour already carries the live API — `lib/src/config/environment.dart:16-20`:

```dart
prod(
  label: 'prod',
  apiBaseUrl: 'https://api.okuvu.in',
  wsBaseUrl: 'wss://api.okuvu.in',
),
```

so `--flavor prod --dart-define=FLAVOR=prod` alone resolves to `https://api.okuvu.in` (proven in §8),
and `BASE_URL` / `WS_URL` were additionally passed with the same values so the requirement is
explicit in the command line rather than implicit in the enum.

Cognito values (client pool, not the therapist pool) came from the running API's own environment —
the same values the API validates tokens against:

### Two failed attempts, recorded honestly

**(a) 19:54:41Z — kernel OOM.** First run (identical command, with `--no-pub`) died at 225 s:

```
* What went wrong:
Gradle build daemon disappeared unexpectedly (it may have been killed or may have crashed)
Gradle task bundleProdRelease failed with exit code 1
BUILD_EXIT=1 / BUILD_END 2026-10-28T19:58:27Z
```

`/sys/fs/cgroup/memory.events` `oom_kill` went 3 → 5 (two processes), host RAM 7.9 GB with no swap
and other agents' builds running (`frontend_server` ~1 GB, tsserver ~0.7 GB). Same known trap as
E18-S2. `android/gradle.properties` is already tuned (`-Xmx1280m`, `workers.max=1`, in-process
Kotlin, no Jetifier) and was **not** changed; the retry waited for a window of ≥2.8 GB
`MemAvailable` (a bounded wait loop, no config change).

**(b) 20:10:07Z — `--no-pub` compiled a stale generated registrant.**

```
.../android/app/src/main/java/io/flutter/plugins/GeneratedPluginRegistrant.java:29: error:
  package dev.flutter.plugins.integration_test does not exist
.../android/app/src/main/java/io/flutter/plugins/GeneratedPluginRegistrant.java:44: error:
  package pl.leancode.patrol does not exist
2 errors
BUILD_EXIT=1 / BUILD_END 2026-10-28T20:11:51Z
```

Diagnosis: `GeneratedPluginRegistrant.java` is **tracked in git** (it is a generated file — "Generated
file. Do not edit.") and its committed copy registers the dev-only plugins `integration_test` and
`patrol`. A release build excludes dev dependencies from the Gradle classpath, so compiling the
committed copy fails. With `--no-pub`, `flutter_tools` skips
`regeneratePlatformSpecificTooling` entirely (`flutter_command.dart:2056: if (!shouldRunPub) return;`),
so the stale file is never rewritten. The successful run therefore drops `--no-pub`: pub runs, the
tool regenerates the registrant with `releaseMode: true` (dev plugins filtered out,
`flutter_plugins.dart:1425-1428`) and the build compiles.

The regenerated file was restored afterwards so this branch carries no source change
(`git checkout -- .../GeneratedPluginRegistrant.java`, `git status --short` empty). See §10.

## 10. Repo defect found, not fixed (deliberately out of scope)

`apps/mobile/android/app/src/main/java/io/flutter/plugins/GeneratedPluginRegistrant.java` is
**committed** despite being generated, and its committed content registers the dev-only plugins
`integration_test` and `patrol`. Consequence: any release build that passes `--no-pub` fails at
`compileProdReleaseJavaWithJavac`. It works with pub enabled (the tool regenerates the file per
build), which is what this build does.

Fix belongs to a separate cleanup (delete the tracked file and add it to `.gitignore`, or keep the
tracked copy free of dev plugins). It was **not** done here because it changes the repo outside this
story's scope and would affect debug/integration-test plugin registration; the regenerated file was
restored so the branch is source-clean.

## 11. What this does NOT prove / not done

- **No device or emulator run.** The host has no emulator/device, so "builds against the live API" is
  proven at the artefact level (defines baked into the AOT snapshot + config resolution) and by the
  live `/health` check — the app was not launched against the API.
- **No Play upload / no release rollout.** The bundle is not uploaded, not assigned to a track.
- **No version bump.** `1.0.5+6` is E18-S2's; unchanged here.
- **No `--split-debug-info` / obfuscation**, no ProGuard rule changes, no signing-config changes.
- `aapt2` was run on the universal APK generated from this `.aab` (§6); `aapt2` cannot read `.aab`
  directly. Package/targetSdk were additionally confirmed from the `.aab` manifest via bundletool.
- The v1-only signature and self-signed cert are expected for an upload key; Play App Signing
  re-signs on upload. No `apksigner` v2/v3 verification of a release APK was done.
- Two failed build attempts are documented (§4); the only remedy applied was waiting for RAM and
  dropping `--no-pub`. No Gradle/build config was modified.
- `keystore.properties` exists only in this worktree (mode 0600) and in Secrets Manager; the
  keystore itself was not copied, rotated, exported or backed up.
