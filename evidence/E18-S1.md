## Step 2 — Key generation (outside the repo)

Keystore: `/opt/data/okuvu/keys/okuvu-upload.p12` — directory `700`, file `600`.
Password: `python3 -c "import secrets;print(secrets.token_urlsafe(32))"`, generated in the
same shell, written straight to a `600` file, and passed to `keytool` with
`-storepass:env` so it never appears in argv, in `ps`, or in this log.

```bash
umask 077
export JAVA_HOME=~/.local/jdk-17; export PATH="$JAVA_HOME/bin:$PATH"
KEYDIR=/opt/data/okuvu/keys; KS="$KEYDIR/okuvu-upload.p12"; ALIAS=upload
mkdir -p "$KEYDIR"; chmod 700 "$KEYDIR"
PW=$(python3 -c "import secrets;print(secrets.token_urlsafe(32))")
printf '%s\n' "$PW" > "$KEYDIR/keystore-password.txt"; chmod 600 "$KEYDIR/keystore-password.txt"
export STOREPW="$PW"
keytool -genkeypair -keystore "$KS" -storetype PKCS12 -alias "$ALIAS" \
  -keyalg RSA -keysize 4096 -sigalg SHA256withRSA -validity 10000 \
  -dname "CN=Okuvu, OU=Mobile, O=Okuvu Technologies, L=Mumbai, ST=Maharashtra, C=IN" \
  -storepass:env STOREPW -keypass:env STOREPW
chmod 600 "$KS"; unset STOREPW PW
```

Output:

```
Generating 4,096 bit RSA key pair and self-signed certificate (SHA256withRSA) with a validity of 10,000 days
	for: CN=Okuvu, OU=Mobile, O=Okuvu Technologies, L=Mumbai, ST=Maharashtra, C=IN
generated: /opt/data/okuvu/keys/okuvu-upload.p12
-rw------- 1 hermes hermes   44 Oct 28 15:04 keystore-password.txt
-rw------- 1 hermes hermes 4424 Oct 28 15:04 okuvu-upload.p12
700 /opt/data/okuvu/keys
600 /opt/data/okuvu/keys/okuvu-upload.p12
600 /opt/data/okuvu/keys/keystore-password.txt
```

`keypass` == `storepass`: the JDK's PKCS12 implementation ignores a distinct key password
and stores it silently equal to the store password, so one value avoids a mismatch that
would only surface at signing time.

## Step 4 — Signing wiring (committed)

Four non-secret files changed:

**`apps/mobile/android/keystore.properties.example`** — template, placeholders only:
`REPLACE_WITH_STORE_PASSWORD`, `REPLACE_WITH_KEY_PASSWORD`, `keyAlias=upload`,
`storeFile=/absolute/path/to/okuvu-upload.p12`, `storeType=PKCS12`, plus a header saying
the file holds a secret, that it is gitignored, and where the real values live.

**`apps/mobile/android/app/build.gradle`** — three behavioural changes:

1. `hasReleaseKeystore` also requires `storePassword` and `keyAlias` to be present, so a
   half-filled `keystore.properties` is treated as "no keystore" instead of failing with a
   cryptic NPE.
2. `keyPassword` falls back to `storePassword`, and `storeType` defaults to `PKCS12`.
3. `release` now gets `hasReleaseKeystore ? signingConfigs.release : signingConfigs.debug`
   — a release build **uses the real upload key when present, and still builds with the
   debug key when absent** (previously it produced an unsigned artifact). `bundle*Release`
   still fails fast without the real key, and `assemble*Release` logs a loud warning, so a
   debug-signed artifact cannot be uploaded by accident.

**`.gitignore`** (root) — added `*.jks`, `keystore.properties` next to the existing
`*.p12`.

**`apps/mobile/.gitignore`** — added path-agnostic `keystore.properties`, `*.jks`, `*.p12`.

## Step 6 — Offline custody (human step, not performed here)

The password is in AWS Secrets Manager and in `/opt/data/okuvu/keys/keystore-password.txt`
(mode `600`). **Both are online.** Losing the keystore or its password means the app can
never be updated on Google Play again under `ai.okuvu.app`: the upload key can be reset
once per app via Play Console support, but losing the key without a working reset means a
new listing and losing all installs and reviews.

The human must:

1. Copy **both** files to an encrypted offline medium (e.g. an encrypted USB stick or a
   VeraCrypt volume) and store it in a physically separate location from the build host:
   * `/opt/data/okuvu/keys/okuvu-upload.p12`
   * `/opt/data/okuvu/keys/keystore-password.txt`
2. Also export the **PEM** copy (`openssl pkcs12 -in okuvu-upload.p12 -nodes -out
   okuvu-upload.pem`) and keep it with the same backup; the PEM survives tooling changes
   that might drop PKCS12 support.
3. Record the SHA-256 fingerprint
   `54:54:26:D0:68:26:8C:98:3F:D0:E6:E6:29:21:31:5A:CF:B4:BD:AA:18:EE:38:E7:94:DA:41:DF:E7:8E:1A:39`
   in the release runbook so a future operator can prove which key signed a build.
4. Verify the copy by restoring it to a scratch directory and running `keytool -list -v`
   against it, then deleting that scratch copy.
5. Store the secret-store recovery path (the account and secret name, not the value) with
   the backup, so that a lost AWS account does not also lose the keystore.

Do not email the keystore, do not put it in a repo, a CI variable store only, or a cloud
drive that syncs to the build host.
