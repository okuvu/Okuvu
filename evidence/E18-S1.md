## What this proves

- Identity is production: `CN=Okuvu, OU=Mobile, O=Okuvu Technologies`.
  The previous placeholder carries `OU=DO NOT SHIP`; that string is absent here.
- 4096-bit RSA with SHA256withRSA — Play's minimum is 2048-bit RSA.
- Valid until 2054-03-15, well past Play's 2033 requirement for new upload keys.
- Serial 4bf14a1697f98065 is unique to this key.

## Secret storage

```
$ aws secretsmanager describe-secret --secret-id evia-beta/android-upload-keystore
2026-10-28T15:04:41.512000+00:00    evia-beta/android-upload-keystore
```

The keystore is at `/opt/data/okuvu/keys/okuvu-upload.p12` (mode 0600, outside the
repo) with the password at `/opt/data/okuvu/keys/keystore-password.txt` (mode 0600).
Neither path is tracked: `keys/` is gitignored and the files never appear in
`git ls-files`.

## Outstanding — human owned, blocks nothing on the agent path

Offline backup of `okuvu-upload.p12` and its password. If this pair is lost, the
app can never be updated under the same identity again; a new upload key can be
registered with Play support, but only with proof of ownership and a delay.

## What this does NOT prove

Nothing about the signing wiring inside the Gradle build — that the release build
actually uses this key is E18-S2's acceptance criterion, and E18-S3 proves the
resulting bundle is signed by this fingerprint.
