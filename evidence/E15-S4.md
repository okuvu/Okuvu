## 2. Code change — `apps/api/src/routes/health.ts`

`commit` is read per request from `GIT_COMMIT`, with a blank/unset fallback of `'unknown'` so the
route can never throw. `status` and `timestamp` are untouched.

```ts
export function resolveCommit(): string {
  const commit = process.env.GIT_COMMIT?.trim();
  return commit && commit.length > 0 ? commit : 'unknown';
}
...
      reply.send({
        status: 'ok',
        timestamp: new Date().toISOString(),
        commit: resolveCommit(),
      });
```

The field is *also* declared in the Fastify `200` response schema
(`commit: { type: 'string' }`) — the response serializer silently drops properties that are absent
from the schema, so omitting that line would have produced a route that "works" in the handler and
still returns no commit over the wire.

## 3. Infrastructure — `infrastructure/aws/evia-beta/ecs.tf`

```hcl
      environment = concat(local.shared_environment, [
        { name = "PORT", value = tostring(var.api_container_port) },
        # E15-S4: images are tagged with the git commit SHA, so var.image_tag
        # *is* the deployed commit. ...
        { name = "GIT_COMMIT", value = var.image_tag },
      ])
```

`var.image_tag` is the same variable that builds the container `image`
(`${aws_ecr_repository.main["api"].repository_url}:${var.image_tag}`), so the advertised value is
the tag by construction. It is set on the **api** container only — `local.shared_environment` is
shared with the worker, and this story is about the api health endpoint.

## 4. Pipeline — `scripts/ecs-image-pin.py`

Terraform is not the only writer of task definitions. `buildspec.yml` (post_build) and
`scripts/deploy-beta.sh` / `deploy-worker.sh` all `describe-task-definition`, rewrite it with
`scripts/ecs-image-pin.py`, and `register-task-definition`. Without a change there, every pipeline
rollout would carry the *previous* `GIT_COMMIT` forward and the endpoint would lie after the first
deploy. The script now derives it from the tag it pins:

```python
def tag_of(image: str) -> str | None:
    """Return the tag portion of an image reference, or None if untagged. ..."""
    if "@" in image:
        return None
    last = image.rsplit("/", 1)[-1]
    if ":" not in last:
        return None
    return last.rsplit(":", 1)[1]
...
    advertised = commit or tag_of(image)
    if advertised:
        target["environment"] = upsert(
            list(target.get("environment") or []),
            {"name": "GIT_COMMIT", "value": advertised},
        )
```

`--commit SHA` overrides the derived value; a digest reference (`repo@sha256:…`) carries no tag, so
the existing value is left alone rather than being replaced with junk.

Proven with a synthetic task definition shaped like `evia-beta-api`:

```
$ python3 scripts/ecs-image-pin.py /tmp/td.json /tmp/td.pinned.json \
    "562654496378.dkr.ecr.ap-south-1.amazonaws.com/evia-beta/api:deadbeef1234"
{
  "containerDefinitions": [
    {
      "name": "api",
      "image": "562654496378.dkr.ecr.ap-south-1.amazonaws.com/evia-beta/api:deadbeef1234",
      "environment": [
        { "name": "NODE_ENV", "value": "production" },
        { "name": "GIT_COMMIT", "value": "deadbeef1234" }
      ]
    }
  ]
}
```

(`GIT_COMMIT` followed the new tag, and the read-only fields the API rejects are still stripped.)

## 7. What is **not** proven here

The last clause of the acceptance criterion — *"a commit field equal to the deployed image tag"* —
**cannot be confirmed until the next build is deployed**. Nothing in this branch has been applied or
rolled out: no `terraform apply`, no `aws ecs update-service`, no CodeBuild run. At the time of
writing the live endpoint still returns `{"status":"ok","timestamp":"…"}` with no `commit`, and the
running task definition `evia-beta-api:11` has no `GIT_COMMIT` (both captured above).

After the orchestrator deploys, the acceptance check is:

```
curl -s https://api.okuvu.in/health            # expect {"status":"ok","timestamp":"…","commit":"<sha>"}
aws ecs describe-services --cluster evia-beta --services evia-beta-api --region ap-south-1 \
  --query 'services[0].{desired:desiredCount,running:runningCount}'
aws ecs describe-task-definition --task-definition evia-beta-api --region ap-south-1 \
  --query 'taskDefinition.containerDefinitions[0].{image:image,commit:environment[?name==`GIT_COMMIT`].value}'
```

and the commit must equal the image tag in the same response.
