# E15-S5 — Terraform owns every beta resource

Acceptance criterion (verbatim): *"terraform plan in infrastructure/aws/evia-beta reports no changes;
the three ECS services, both target groups, all ALB listener rules and all DNS records are in
state; no resource in the beta account is hand-created and untracked"*

Scope honoured: worktree `/opt/data/okuvu/wt/E15-S5` (branch `feat/E15-S5-tf-ownership`, base
`4c8809b`). **No `terraform apply`, no `terraform import`, no `git push`, no `develop`.** The real
state file in the orchestrator's checkout was read, copied, and never written — its md5 and mtime
before and after the audit are in §8. All timestamps UTC. Secrets: names and ARNs only, no values.

Audit window: 2026-10-29 04:55Z → 05:10Z. Each transcript below is verbatim from the run; the
`ls -l` listing at the end of §8 shows when each was captured.

So state is `infrastructure/aws/evia-beta/terraform.tfstate`, gitignored, single machine, no
locking, no remote backup. Serial 268, lineage `7dd7f7f3…`, written by Terraform 1.9.8:

```
$ python3 -c "...json.load(open('terraform.tfstate'))..."
```

**Consequence for the orchestrator:** the import commands in §6 are only safe from the working
copy that holds this exact state file, and only one at a time. Importing from a second checkout
creates a second, empty state and silently orphans the real one. Creating the commented-out S3
backend is the prerequisite for anyone else ever touching this stack.
