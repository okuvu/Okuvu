## 1. The criterion I corrected, and why it stays on the record

The original wording required the journey to *"send a turn and receive an agent reply inside the
portal"*. Checking the code showed that assumption is wrong about the product: `apps/therapist-portal`
has 13 pages, none is a conversation view, it contains **zero** references to `api.okuvu.in`, and it is
deliberately DB-direct. The design is **client chats in mobile, therapist reviews in portal**.

So the journey was restated as login → caseload → open client → review that client's conversation →
save note, and the missing review UI became its own story, **E16-S9**. Nothing was marked verified by
that correction alone — E16-S5 stayed `not_started` until the runs below actually passed.

## 3. Data prerequisites, and what is fixture

The journey needs a therapist–client pair and turns to review. Both now exist:
`scripts/seed-client-demo.sql` creates **one** `TherapistClient` row (ananya.rao@okuvu.in ↔ the one
client with a real session) and two short synthetic sessions (8 turns, fixed ids `b16c0000-…`). The
client's three real turns — produced by Qwen through the live websocket during E17 work — sit in the
same transcript.

Honesty markers, so a later reader cannot mistake fixture for clinical data:

- Seeded assistant turns carry `model_version = NULL` (which already means "no model call produced
  this").
- There is deliberately **no** `ClinicalConfig` row: a care plan is a clinical assignment, so the
  client shows as care-plan-unassigned rather than being given an invented CP1.
- The three notes created by these runs are real rows from the real mutation, and their text says
  exactly what they are: `E16-S5 smoke test note (run N) — not clinical guidance, safe to delete.`
  Notes from earlier debugging runs were deleted before the three consecutive runs, so the table
  holds exactly the three.

## 4. What this does not prove

- It does not prove the **mobile client** journey (a different app, different stories).
- It does not prove paging: the transcript is 10 turns, under the 50-turn page size, so
  `nextCursor` was never exercised live. The cursor path is covered by unit tests
  (`clients-conversation.test.ts`), not by this walk-through.
- It runs against production beta data, which is seeded — five real therapists on five real devices
  is E20-S1, still gated on the Play submission.
