## 2. The actual gap: nothing could ask which agents exist

`roster.ts` holds the 15 agents as data and `validateRoster()` enforces the authority rules, but no
route, command or export listed them. That is precisely the failure mode `docs/AGENTS-15.md` opens
with — a directory with 4 of 15 agents next to a document asserting 15, with no mechanical way to
settle it. `grep -rn roster apps/api/src/routes` before this change: **no matches**.

Built `GET /agents/roster` in `apps/api/src/routes/agents.ts`, registered in
`apps/api/src/routes/index.ts`.

### Why this shape, and not a new registry

* **It projects `ROSTER`; it does not restate it.** `buildRosterResponse()` maps `ROSTER` at request
  time. Adding an agent to `roster.ts` is the *only* edit needed for it to appear — the
  self-registering property, with no second list to drift. `AGENT-CODE-STANDARD.md` §1 and §11
  forbid a second registry next to `roster.ts`; this adds a view, not a registry.
* **Identifier is the stable key.** `id` (`A1`…`A15`) is the same string the pipeline, the tests and
  the docs use; `name`/`purpose` are display text and are not treated as identity.
* **Fail closed (standard §4).** If the roster breaks its own invariants the endpoint answers
  **503 `ROSTER_INVALID`** with the violated rule codes instead of serving an authority model it
  cannot honour. The worst version of this endpoint is one that happily publishes "A12 and A2 may
  both write client-facing text".
* **Same gate as every other non-health route** — `preHandler: [verifyCognitoJWT]`. Internal
  metadata, but the deployed API has no anonymous surface apart from `/health`.
* **`writes` is sorted** so the payload is byte-stable across calls and diffable.

## 4. Absence of A9-post and J2 — three independent proofs

1. **By identifier.** The endpoint's id list equals `ROSTER_IDS` exactly; `A9-post`, `A9POST`, `J2`,
   `A16` are each asserted `not.toContain`.
2. **By raw body text.** The whole serialised body is lowercased and asserted free of `a9-post`,
   `a9post`, `journal-prompt` and `"j2"` — so they cannot creep back in as a `name` or a `purpose`.
3. **By construction.** Feeding a roster that contains `A9-post` or `J2` into `validateRoster()`
   yields `roster_incomplete` naming the id in its `unexpected: [...]` detail. They are not "left
   out" — adding them is a failing test, and the endpoint would then 503 instead of publishing them.

Both remain what they are: `a9-post/` is the pre-publication review of A2's draft (part of A9's job)
and `journal-prompt/` is J2's prompt generator — components, not roster members
(`docs/AGENTS-15.md`, `roster.ts` header comment).
