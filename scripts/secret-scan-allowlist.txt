# Secret-scan allowlist — read by scripts/secret-scan.py.
#
# This file suppresses findings. Treat every entry as a paragraph in the pull
# request, because that is what it is: a claim that a string that looks exactly
# like a credential is not one.
#
# Format. Entries are blocks, each beginning with a section header:
#
#   [[working-tree]]            silence a finding in the working tree
#   rule   = <rule name>        one of the names printed by the scanner
#   path   = <path from repo root>
#   reason = <why this is not a credential — at least 20 characters>
#
#   [[history]]                 silence a finding in git history
#   rule   = <rule name>
#   path   = <path from repo root>
#   reason = false positive: <why the historical match is not a credential>
#
# Rules of the road:
#   * A missing, unreadable or malformed allowlist FAILS the build (exit 2).
#     The file is required, not optional.
#   * An entry without a `reason` of real length FAILS the build. So does an
#     unknown rule name, an unknown key, a duplicate key or a key outside a
#     section. There is no "ignore everything" switch and no wildcard path.
#   * [working-tree] entries do not apply to history, and [history] entries do
#     not apply to the working tree. A new secret in the tree is never
#     suppressible by citing an old one.
#   * [history] entries only silence *documented false positives*. A real
#     leaked credential in history stays in the report: the report is the
#     inventory that docs/SECRET-REMEDIATION.md is written against, and hiding
#     an item from it hides the reason to rotate.
#   * Prefer fixing the rule over allowlisting the file. A placeholder such as
#     `postgresql://user:***@host/db` is already handled by the scanner's
#     placeholder filter; it does not need an entry here.
#
# Entries are matched on (rule, path), so annotate the reason with the line
# numbers it covers when a single path has several.
#
